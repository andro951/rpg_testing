How to write a path:
- Start at the whole JSON value. Every non-empty path starts with /. Each slash separates the next part, except a slash inside a quoted JSON string belongs to that string.
- Within an object, a part names a property exactly. In an unquoted property name, write ~ as ~0 and / as ~1. A property name can also be written as a JSON string.
- Within an array of objects, a part is the JSON value of the object's designated ID field, as named in the database structure.
- Within an array of strings, numbers, booleans or null values, a part is the actual JSON value of the element.
- Strings must include their JSON quotation marks and normal JSON escaping. Numbers, booleans and null are unquoted. The number 42 and the string "42" select different elements.
- For example, /elements/"element-a"/status selects the status field of the element whose designated ID is "element-a". /places/"place-a" selects the string "place-a" itself. /numbers/42 selects the number 42 itself.
- Quotes and backslashes inside a string follow normal JSON escaping. A slash inside a quoted string needs no special escape: /items/"item/17" selects the ID "item/17".
- An empty path string refers to the whole JSON value. A path consisting of one slash refers to a property with an empty name. A quoted empty string inside a collection selects the empty-string value or ID.
- Each collection selection must match exactly one element.
- A path is itself a JSON string in the output operation. Keep the quotation marks around string selectors, then escape them inside the path or from field: the path /elements/"element-a"/status is written as "path": "/elements/\"element-a\"/status".

Only these five operations are allowed:
1. Update: use "op": "replace", "path" for the existing field, and "value" for its new value. The path selects a field inside an object. Do not replace an entire collection or a whole element selected from a collection.
2. Append: use "op": "add", "path" for the destination collection itself, and "value" for the complete element to append.
3. Remove: use "op": "remove" and "path" for the collection element selected by its unique value or ID. Do not remove an object field.
4. Move: use "op": "move", "from" for the collection element selected by its unique value or ID, and "path" for the destination collection itself. Transfer the whole element to the end of that other collection. Do not reorder elements within one collection.
5. Copy: use "op": "copy", "from" for the collection element selected by its unique value or ID, and "path" for the destination collection itself. Append a complete copy to the end of that other collection, keeping the source element unchanged in its original collection.

Operations apply in the order you return them. Resolve each path against the current data when that operation is applied. These value-based paths are a custom format, not standard JSON Pointer paths.
