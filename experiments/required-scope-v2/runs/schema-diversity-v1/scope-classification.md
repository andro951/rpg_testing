# Scope classification: schema diversity and array boundaries

Repository AGENTS.md, Development rules, states the current scope as fixed-schema updates to existing fields and unique-ID/value array-element additions and removals. The reviewed prompts also explicitly permit a collection part to identify its unique ID or primitive value and require exactly one match. Accordingly, primitive-element operations here are classified as unique-value array operations under the repository contract, not whole-field replacements. The input values are unique in each relevant array, removed values exist exactly once, and added values are not already present. The case-specific evaluator and original outcomes remain unchanged.

Schema-diversity: party_remove_role removes the unique primitive value scout; party_multiple appends the unique primitive value cook after an existing-field update. The other four cases operate on existing fields or objects selected by their unique IDs.

Array-boundaries: append_empty adds Museum, append_ingredient adds yeast, remove_ingredient removes salt, and cross_branch removes Park before an existing-field update; these are primitive-value array operations. append_object_empty adds an object with a unique isbn, and remove_object_nested removes an object identified by isbn. The array-boundaries cohort is kept separate from schema-diversity and earlier evidence. Reports should additionally distinguish primitive-value cases from object-ID cases, so readers using an object-ID-only interpretation can exclude the former. The older quoted user wording referenced unique IDs; this classification relies on the repository's more explicit later ID/value instruction, rather than asserting that the earlier quote itself said primitive values.
