## Findings

- Earlier 114/114 scores did not generalize to all new tasks. The initial holdout used one synthetic schema and six tasks; its four Unity configurations and five desktop models exposed meaningful failures under deeper nesting, array changes, awkward identifiers and ordered operations.
- Schema-diversity introduced three different schemas. Object-ID/field-only results are reported separately from unique-value primitive array operations. The repository's later AGENTS.md scope explicitly includes unique-ID/value element operations; the older user quote mentioned unique IDs without explicitly mentioning primitive values.
- ID routing tested the same child ID in different parent collections, with uniqueness maintained within each collection. Dot JSON passed 51, 51, 54, 33 and 54 of 54 across the five desktop models; slash JSON passed 18, 33, 6, 12 and 6; path list passed 51, 48, 33, 9 and 39. This compares whole recipes.
- Array scale compared last-element update/removal at 4, 8 and 16 items. Four non-2B models passed all 54 dot and all 54 path-list observations; the 2B model had identical per-length scores for each recipe in this small set. Size, input length and target ID changed together, so no pure length effect or general threshold is established.
- Multiple-change compared one with three ordered operations across three schemas. Results vary by model and complete recipe; task content and operations also change, so change count cannot be isolated as the cause.
- Reserved-ID tasks revealed a presentation effect: every path-list pass across five models came from the full-path view, which supplies encoded paths. Most of 459 failures had recorded parser/resolver errors; three valid responses targeted the unchanged identifier rather than the requested amount. The record cannot prove the model's mental reason.
- The paired confirmation used three fresh schemas and plain/reserved ID substitutions with equivalent normalized source, task and expected state. Across five models and 135 matched pairs per recipe, plain-pass/reserved-fail counts were 82 dot JSON, 84 path list and 6 slash JSON. Four slash pairs went the other way. These are 27 pairs per model/recipe from only three underlying tasks, with repeated presentations, so they are not independent population estimates. Inputs and encoded paths necessarily changed along with identifier characters.

## Next step

The evidence justifies reviewing whether an improved deployable recipe can handle reserved identifiers while retaining strong performance on ordinary IDs, followed by evaluation on newly held-out cases. Creating or tuning a remedy changes the fixed recipes and was not authorized in this round. Repeating synthetic cases with the same fixed recipes would add little without a new hypothesis, so no further desktop inference was launched. Perchance needs permitted identification or user confirmation of the listener/profile before a retry; process-name and port checks alone do not establish ownership.
