# Literal-text whitespace and capture diagnostic

## Result

The local llama.cpp capture path did not strip the tested content after receiving it. Synthetic tests ran 96 cases on each of the literal v1 and v2 runtimes, using the real SSE transport parser, `NativeBackend.generate`, workflow, JSON result store/readback, literal parser, state scorer, and independent evaluator. The HTTP response was a deterministic in-memory stand-in, not a real model or HTTP server. Tests split response content into short JSON SSE deltas and checked exact text and state at each stage. Cases covered target text in the first, middle and last updates, literal leading/trailing spaces and encoded spaces, final newline present and absent, empty text, literal backslash-n versus newline, and literal backslash-quote.

The transport does call `.strip()` on the outer SSE `data:` frame before JSON decoding; it does not strip the JSON string in the content delta. Captured delta strings are concatenated without trimming, passed to the workflow as text, saved and reloaded without modification, and decoded by a parser that splits on physical newline without stripping line content. Native helper `.strip()` calls found in diagnostics/readiness and runtime log handling are not in the returned model-content path. This finding applies to the tested local llama.cpp path, not the separate Perchance browser provider or unobserved processing inside a model server before it supplies SSE content.

All 54 literal-v1 development observations were checked: concatenated captured SSE content exactly equals both the recorded call text and workflow output. For the nine development whitespace observations, the expected value was `'  keep spaces  '`. Every captured stream contained `set service.tickets.t1.message: text:  keep spaces` with no trailing spaces. Thus in these records the requested spaces were already absent at the captured provider response; there is no evidence that this harness removed them. This does not establish what the model internally intended. No old scores, records, parsers or prompts were changed.

## Simpler representation assessed

The prototype `marker.py` is a separate, unintegrated representation idea descending conceptually from the original dot-path baseline. String updates use `set path: text:<literal>|`, with the final `|` as a required end marker. For example, `set a.note: text:  padded  |` makes the trailing spaces visible before the marker. An empty string is `text:|`; a value ending in a literal pipe uses two pipes at the end (`text:ending||`), because only the final pipe is structural. Other pipes and quotes inside the value need no escaping. Backslashes, newlines, carriage returns and tabs still use explicit escapes; non-string values remain JSON and add/remove operations retain existing dot-path identity semantics. This removes the v2 requirement to encode every trailing space as `\s`, but introduces one required marker and does not eliminate all escaping.

`test-marker.py` passed 78 deterministic encode/decode/application cases covering first/middle/last operations, whitespace, empty strings, pipes in all positions, literal backslash-n versus actual newline, backslash-quote, quotes, delimiters and final newline present/absent. Separate checks covered nested object append, identity removal, preservation of unrelated state, no-op and malformed output. This is a parser prototype, not a deployed method or model comparison. It has not been submitted to any model, and there is no evidence that models will emit the marker or preserve spaces more reliably. A defensible comparison would first test a development-only candidate derived from the original baseline, then predeclare and validate fresh, independent heldout cases before selecting a candidate; no heldout result should be used to tune it.

## Controller exits

The safe-text controller exited during a model load after 162 saved observations; the restructured-copy controllers exited after six saved observations and later during a fourth-model request. Saved statuses remained stale and an orphaned owned model server remained in each case. No Python wrapper exception was recorded, and the checked application error events did not identify a cause. The precise cause remains unknown; this evidence does not establish an operating-system, runtime or harness defect. The owned orphaned servers were stopped, completed observations retained, and a potentially in-flight case from each restructured-copy interruption was excluded rather than replayed. Later continuations completed the remaining planned cases. No denied process inspection was retried or bypassed.

## Reproduction

From the task workspace, run the project's `.venv-workbench` Python with `literal-text-branch-v2/pipeline-whitespace-diagnostic.py` and again with `--v1`, then `literal-text-branch-v2/audit-dev-capture.py`, and `literal-text-marker-assessment/test-marker.py`. These scripts make no inference calls. The development audit reads immutable local records; the synthetic pipeline uses a temporary result store.
