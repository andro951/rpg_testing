# Reserved-ID failure review and paired confirmation rationale

The preceding reserved-id-v1 cohort has 459 assessed failures across five local models. Of those, 456 have a recorded score error and three are semantic failures without a recorded parser/resolver error. These categories are based on recorded diagnostics, not independent proof of the model's intent.

- Selector escaping: dot and path-list outputs often supplied raw separators, quotes, Unicode or percent signs instead of the contract's encoded component. Example: dot output path board.cards.snow-雪.done produced a reserved-character escape error. Some outputs split A.B into separate path segments, resulting in a selector resolution error.
- Output syntax and slash selector syntax: some path-list outputs omit the operation keyword or have malformed brackets; slash paths often emit unquoted string selectors, producing the parser error that an array component must be a JSON scalar. These diagnostics may overlap with an incorrect target; the error alone does not distinguish intent.
- Valid but wrong target: three dot-JSON outputs targeted the order_id field and set it to its current value instead of updating amount; the parser accepted them, the expected change was missed, and the evaluator correctly marked failure.
- Task misunderstanding versus syntax: examples such as a whole-object replacement or an identifier field update depart from the requested field operation. A response alone cannot establish whether the model misunderstood the task, misidentified a path, or made a formatting error; the review does not assign a mental cause.

All raw observations and original outcomes remain in reserved-id-v1. The new paired-id-characters-v1 uses three fresh schemas with matched plain/reserved ID substitutions, preserving all existing recipes and parsers. After ID normalization each pair matches in source, expected state, schema and task. Input characters and length necessarily differ. Three tasks, three presentations and three repetitions give 27 matched plain/reserved pairs per recipe/model. The predeclared purpose is to test sensitivity to these identifier substitutions, not to tune a prompt or claim a universal causal effect.
