## Syntax and interpretation

`dot_patch_v1` paths have no leading slash, dollar sign or dot. For example, `items.item-17.count` selects count on the element identified by item-17. `locations.town-a` selects a primitive element; `storage` selects a destination collection. The empty path string selects the root. Object fields and collection identities are resolved using the actual state and declared schema. Collection selection never uses array positions.

String identities use their contents; other scalar identities use their JSON spelling. Plain text is matched against actual identities, with no numeric/boolean/null type guessing. Thus a collection containing both numeric 42 and string "42" is ambiguous under this method and is rejected. Quoting a component does not bypass this ambiguity. The strict slash control can still distinguish those identities.

Within one component, only ASCII letters, digits, hyphens and underscores are literal. All other UTF-8 bytes use `%HH`: dot `%2E`, percent `%25`, quote `%22`, slash `%2F`, backslash `%5C`, colon `%3A`, literal @ `%40`. Hex escape case is accepted and normalized to uppercase. The sole component `%_` represents the empty string; literal percent-underscore becomes `%25_`. NUL is `%00`, distinct from the empty string. Dots between components remain separators. Non-ASCII and whitespace use UTF-8 escapes. Unknown or invalid UTF-8 escapes are rejected.

`@` is never a selector marker. A literal @ inside an ID is represented by `%40`. IDs containing dots are escaped, rather than split or guessed. The Full paths renderer displays dot paths immediately followed by a colon and JSON value, and keeps empty arrays/objects visible. Literal separators inside fields and IDs are encoded by the existing dot-path encoder, never by slash-to-dot text replacement. Dot notation applies to both flattened input paths and output operation paths.

## Path-only normalization and grading

After the complete response has passed strict JSON parsing, the new method can normalize a JSON-quoted component inside path/from, for example `items."item-17".count` becomes `items.item-17.count`. A quoted component containing a literal dot is escaped as one component. This compatibility behavior belongs only to the versioned dot method. Malformed outer JSON is not repaired, and no quote is removed from a `value`, ID field or other data. Raw responses remain immutable; any normalization is deterministic interpretation of path/from content.

The response schema retains the five operation-object shapes and string path/from fields. Runtime resolution validates paths against the sequential state and schema. The existing strict operation roles enforce field Update, collection Append, whole-element Remove, cross-collection Move and independent Copy. Destinations select collections themselves. Same-collection and descendant transfers remain unsupported. Schema violations and duplicate/ambiguous IDs fail.
