Authoring layers:
  test_builder/database-rules.txt — shared database requirements for all methods.
  test_builder/methods/value_patch.txt — the active shared explanation of all
    five operations, typed value selection and empty lists. No @ or array indexes.
  Standard positional JSON Patch prompt generation is retired. Its original
    templates and evidence remain archived; its legacy evaluator stays available.
  test_builder/templates/*.txt — reusable tasks, separate from method instructions.
    Nested element updates and no-change cases reuse the element-update template.
  test_builder/fixtures.json — predefined schemas, synthetic data, identifier
    fields/values and task parameters. No expected answers are stored here.
  test_builder/builder.py — method registry and assembly. Future methods need a result adapter/
    reference encoder. Task data and final-state oracles can be reused.
  test_builder/presentation.py — schema-aware ID dictionary and full-path views.
    Dictionary keys copy each object element's declared ID value and retain its
    ID field. Primitive elements use their own value. JSON keys are strings;
    non-string IDs use JSON spelling. Colliding keys are rejected, never merged.
    Full-path lines use the actual value-selection path immediately followed by
    a colon and JSON value, with no outer path quoting or separator whitespace.
    Example: /people/"jx1b"/hair:"black". Empty containers stay visible as []/{}.

The selected operation and path method is explained rather than assumed.

inserted once, so marker-shaped strings are not interpreted as templates.

Grading:
  Fixed final states, schema validation and required operation names are checked.
  Only existing-field updates, collection appends/removals and transfers between
  different collections are accepted. Copy/test, field removal, array insertion,
  whole-collection overwrites and whole-element replacements cannot bypass a task.
  Value-path appends and move destinations select the collection itself; numeric
  positions and /- are not append destinations in this method. No-change accepts
  an empty JSON array with any valid JSON whitespace and
  rejects redundant replacements or test preconditions.
  Response contracts are checked AFTER generation. They are never supplied as
  constrained decoding or otherwise assumed available on Perchance.
  Unsupported/ambiguous task inputs and schema/ID violations are rejected before
  exporting a runnable definition. Invalid requests are not treated as no-change.
