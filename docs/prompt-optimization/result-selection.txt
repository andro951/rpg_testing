Starting optimization from a saved result

Open Results in Workbench, then Open results table. Click a result square to open its evidence page. Optimize this prompt (OPRO) opens Prompt Optimization with that exact test, input presentation and recorded model selected. Opening the page does not create a session or start inference. Review the writer/settings and click Start new session.

Starting test and Input presentation can also be selected directly in Prompt Optimization. Tests are grouped by task type. Each new session freezes its selected starting case and expands successful candidates to all compatible cases of the same task type on the models available on that worker. Continue session retains that session's frozen scope, writer and thread.

The selected saved result is copied into the session as immutable reference evidence and included in prompt-writer feedback when its model belongs to the current cohort. It is not an extra scored observation and does not replace the session's baseline trials. Export/import preserves this reference evidence.

Archived, disabled, rejected, unreviewed or changed definitions cannot silently become a different test. A changed definition requires explicitly choosing the current version. A recorded model absent from the worker stays visibly unavailable; choose a replacement explicitly before Start becomes enabled. Loading and failure states are visible, and reopening the tab retries failed discovery.

For a desktop-host/laptop-control arrangement, open the table from the host Workbench's Results page. This keeps navigation on the same host and port. The standalone Open_Results_Table.bat viewer instead opens or starts Workbench on the computer running that viewer after the button is clicked; it checks that the worker belongs to this repository. An older running Workbench must be restarted to load these routes.

Benchmark prompts, saved result bytes, repetition counts and model-generation deadlines are unchanged by this navigation feature. Prompt writing and native model loading retain their existing no-elapsed-timeout behavior.
