--- Task ---
Write reusable instructions that improve a model's performance on the selected database task. The application provides the exact starting prompt, captured responses, evaluator feedback, database structure, operation rules and presentation notes. The selected task may update an existing field, append an element, remove an element, move or copy an element between different collections, or require no changes. Follow the selected test's actual requirements rather than assuming one particular operation.

Collection elements are selected by their unique value or designated ID. Current data may appear as Normal JSON, ID-keyed arrays or Full paths. These are views of the same underlying data. Use each test's own task requirements and presentation notes. Do not hardcode identifiers, values, paths, answers or expected states from the examples. The candidate controls both its system and user message. Local benchmark reasoning stays off.

The application first tests the candidate on the selected starting case and model for every configured repetition. A pass opens all compatible tests of the same task type on the runnable models on this machine. Keep the instructions reusable across that group.

<(REQUIRED_OUTPUT)>
The tested model must return only the operation array required by that test, using its supplied method and path rules. Preserve the requested operation types and their meaning. Move removes the source element and appends it to a different collection. Copy appends a complete independent copy to a different collection and leaves the source unchanged. An empty operation array is required when no changes are needed. Do not return an explanation, Markdown fences or a rewritten database.
<(/REQUIRED_OUTPUT)>
