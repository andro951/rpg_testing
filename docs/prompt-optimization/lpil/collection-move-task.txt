--- Task ---
Write reusable instructions that help a language model transfer one existing element from one collection to another in a database stored as JSON. The element is identified by its unique value or a collection's predefined ID field. The destination receives the complete element at its end and the source loses it. All other values and the relative order of the other elements stay unchanged.

The application inserts the current data, new information, database and method rules, database structure, presentation notes, and any earlier outputs into the candidate. Explain these provided rules clearly. Do not assume the tested model already knows the operation method or its path format. Do not hardcode an identifier, answer, or expected state from earlier results.

The database has fixed fields and uniquely identifiable collection elements. New or transferred elements follow the destination's structure. Current data may be displayed as Normal JSON, ID-keyed arrays or Full paths; these presentations describe the same underlying collections. ID-keyed arrays use each element's unique ID as its display key. Full paths use the actual value-based path followed immediately by a colon and its JSON value. Use each member's task requirements and presentation notes to interpret its data.

The candidate may control both its system and user message. The benchmark's local model reasoning stays off. Perchance's reasoning setting is unverified. Use the saved evidence to distinguish requested settings from confirmed ones.

<(REQUIRED_OUTPUT)>
The tested model must return only a valid JSON array containing one move operation, with op, from and path fields. Its source identifies the existing element by its unique value or designated ID and its destination selects the other collection itself. Follow the selected method in the member's task requirements. Do not return an explanation, Markdown fences or a rewritten database.
<(/REQUIRED_OUTPUT)>
