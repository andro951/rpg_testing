Return only a JSON array of JSON Patch operations. Do not include an explanation, Markdown fences, or the full updated database. Use one operation for each change. If no changes are needed, return an empty array: [].
Each element of the array must be an object with the fields described below.

How to write a path:
- Start at the whole JSON value. Every non-empty path starts with /. Each slash introduces the next part of the path.
- Within an object, a part names a property exactly. Within an array, a part gives the element's position.
- Count array positions from 0: the first element is 0, the second is 1, and so on. An ID value identifies the element to find; it is not its array position.
- In property names, encode ~ as ~0 and / as ~1. To read a path part, replace ~1 with /, then ~0 with ~. Other characters keep their meaning as part of the property name.
- An empty path string refers to the whole JSON value. A path consisting of one slash refers to a property with an empty name. Quotation marks around a path delimit its JSON string and are not part of the path.

Only these four operations are allowed:
1. Update: use "op": "replace", "path" for the existing field, and "value" for its new value. Within a collection element, find that element by its ID, then use its current array position in the path.
   The path selects a field inside an object. Do not replace an entire collection or a whole element selected from a collection.
2. Append: use "op": "add", "path" for the destination array with /- added to its path, and "value" for the complete element to append. The final - means the end of that array.
3. Remove: use "op": "remove" and "path" for the collection element to remove. Find the element by its unique value or ID, then use its current array position in the path. Do not remove an object field.
4. Move: use "op": "move", "from" for the existing element, and "path" for the destination array with /- added to its path. Transfer the whole element to that other collection. Do not reorder elements within one collection.

If there are multiple changes, operations apply in the order you return them. Each path must refer to the data as it exists when that operation is applied.
