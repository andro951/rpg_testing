Generation: materialize.cjs validates each repository template using production validateStoryDefinition, then executes the unchanged production library-worker.js functions compileValidatedStoryIndexes, materializeNewGame and compatibilityRuntimeState. An isolated in-memory adapter supplies the template and compiled indexes instead of IndexedDB. The first authored playable character is selected; no appearance customization or story edits. Isolated saveId 1 is supplied for runtime hydration, exactly as persistence would assign a fresh first save. Output is JSON.stringify(runtimeState,null,2) plus newline. This is the complete fresh runtime state before any gameplay turn, not an existing user's save, synthetic approximation, or copied authored template. No provider call, actual application save, browser session, desktop access, or user history involved. This does not claim a UI playthrough.

Bramble Bridge: default player Rowan Reed; 54 initial records; 16,766 compact UTF-8 JSON bytes, 24,160 pretty file bytes. All 44 arrays audited: empty, unique primitives, or objects with unique explicit id fields. No repairs, extra identity fields or truncation. Runtime includes NPC directory, appearance/outfits, inventory, objectives/branches, world map, memory and clocks.
High Hook: default player Case Mercer; 62,883 compact UTF-8 JSON bytes, 90,920 pretty file bytes. Additional larger candidate only, not yet checked for benchmark array grammar.

Materialization files preserve the engine's initial records/header separately for audit. New-game files are the literal complete compatibility runtime JSON to use as starting-state artifacts. Avoid including materialization metadata in prompts. Full-path formatting/tokenizer costs must be measured separately against the common context budget; do not trim the runtime state to force a fit.
