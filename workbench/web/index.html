Self-contained test files

Recorded evidence

Correct, incorrect and invalid answers are all completed results. Execution skips are recorded; memory failures enter the recovery pass after the primary pass. Aborted cases remain pending. Deleting a result explicitly schedules it again.

Results are loaded outside active benchmark operations. Controlled cache samples with unverified reuse are flagged separately.

Worker log

Live events are buffered in memory. Disk writes and Git publication happen outside measured workflows.



Find GGUF models
Search Hugging Face, inspect every published quantization, and download only the variants you select. Models and partial downloads go directly into your chosen models folder.
Recommendations use download size and format—not measured quality or a promise of GPU fit. No generation settings change here.


Native llama.cpp runtime
The workbench launches and stops its own llama-server. No terminal commands and no LM Studio installation are required.
Installation is always explicit. Files stay under this repository’s .local/runtime folder. Keep a compatible build pinned for consistent experiments; no drivers are installed or updated.


Compare results
Full-GPU, CPU-offloaded, and unverified legacy results remain separate, as do different model files and test versions.


Inference host
Native llama.cpp only. These are one-time operational settings, not per-run test controls.
This folder is only for models. Tests, results, logs, runtime files and configuration remain with the repository. No default C-drive models folder is created.
Never publish private data or credentials to this public repository.


Laptop control through Tailscale
Start this workbench on the desktop once. Then use the same controls from your laptop’s browser. Remote Desktop is not needed. Keep the desktop awake.
The control service binds only to loopback and your Tailscale address. It does not use public port forwarding or Tailscale Funnel. The pairing key grants control; share it only with your own devices.
First launch prerequisites
Python and Git must be available. The launcher can prepare its Python environment after asking permission. Choose your models folder, browse models here, and install or select a native runtime. All downloads require your click.
